# DataModels

This repository contains various data models used for different applications. Each model is defined in its own file within the `models` directory. 

## Supported locales

Every category, unit, series, and visualization configuration must provide translations in English (`en.json`), French (`fr.json`), German (`de.json`), and Spanish (`es.json`).

## Categories

Categories are use to group units or series together and providing translation and seo. They are not bundle on their own in the output files

### Structure

```typescript
// model.json
type CategoryInputModel = {
  key: string; // Unique key of the category
  type: "category";
}

// lang.json
type CategoryTranslationModel = {
  title: string; // Translated title of the category
}

```

### Output 

```typescript
type CategoryOutput = {
  key: string;
  title: string;
}
```

## Units

Units are defined in the `models/units` directory. Similar to series, each unit model is defined in its own folder with a model.json file for the base model and language-specific JSON files for translations.

### Structure

```typescript

// model.json
type SubUnit = {
  key: string; // Unique identifier for the sub-unit
  factor: number; // Number of base units in one sub-unit: valueInBase = value * factor
}

type UnitInputModel = {
  key: string; // Unique identifier for the unit
  type: "unit";
  category: string; // Reference to a category key
  system?: "metric" | "imperial"; // Measurement system
  baseUnit: string; // Reference to the base SubUnit key
  subUnits: SubUnit[];
}

// {lang}.json
type UnitTranslationModel = {
  title: string; // Name of the unit in the specific language
  description: string; // Description of the unit in the specific language
  abbreviation?: string; // Abbreviation for the unit in the specific language
  subUnits: { [key: string]: { abbreviation: string, title: string } }; // Titles for each sub-unit
  seo: {
    keywords: string[]; // SEO keywords
  };
}

```

For example, with `hPa` as the pressure base unit, `Pa` has a factor of `0.01`,
`kPa` has a factor of `10`, and `inHg` has a factor of `33.8639`. To convert
between sub-units, use `valueInTarget = value * source.factor / target.factor`.

DataJot may automatically choose a display sub-unit from the unit's `subUnits`.
Use a dedicated unit with only the intended sub-unit when a template must keep
a fixed display unit. The atmospheric-pressure series and its visualization
configuration use `pressure_hpa` so both values and thresholds remain in hPa.
The general `pressure` unit remains available for other pressure measurements.

### Output

The output models are generated by combining the input models with their respective translations based on the target language. This results in a comprehensive model that includes all necessary information for use in applications.

```typescript

type SubUnitOutput = {
  key: string;
  abbreviation?: string;
  factor: number;
  title: string;
};

type UnitOutputModel = {
  key: string;
  category: CategoryOutput;
  system?: "metric" | "imperial";
  baseUnit: string;
  subUnits: SubUnitOutput[];
  title: string;
  description: string;
  seo: {
    keywords: string[];
  };
}

```

## Series

Series are the main models of the repository. Each series model is defined in its own folder within the `models/series` directory. The model.json file contains the base series model with its id, and language-specific JSON files (`en.json`, `fr.json`, `de.json`, and `es.json`) contain translations for the series name and description.

### Structure

```typescript

// model.json
type SeriesInputModel = {
  key: string; // Unique identifier for the series
  type: "series";
  category: string; // Reference to a category key
  icon: string; // Icon representing the series
  color: string; // Hex color code
  graphType: "line" | "bar" | "area" | "points";
  unit?: string; // Reference to a unit key
  svc?: string; // Reference to a visualization config key
  decimalPrecision?: number; // Number of decimals to display
  aggregationMethod: "average" | "sum" | "last" | "min" | "max"; // Defaults to "average" for standard numeric series
}

// {lang}.json
type SeriesTranslationModel = {
  name: string; // Name of the series in the specific language
  description: string; // Description of the series in the specific language
  seo: {
    keywords: string[]; // SEO keywords
  };
}

```

### Output

The output models are generated by combining the input models with their respective translations based on the target language. This results in a comprehensive model that includes all necessary information for use in applications.

```typescript

type SeriesOutputModel = {
  key: string;
  category: CategoryOutput;
  icon: string;
  color: string;
  graphType: "line" | "bar" | "area" | "points";
  unit?: UnitOutputModel; // Full unit model
  decimalPrecision?: number;
  aggregationMethod: "average" | "sum" | "last" | "min" | "max";
  name: string;
  description: string;
  svc?: SVC;
  seo: {
    keywords: string[];
  };
}
```

## VisualizationConfig

### Structure

```typescript

type ThresholdOperator = "<" | "<=" | ">" | ">=";
type ThresholdAxisLabelDisplayMode = "value" | "label" | "valueAndLabel";

type ThresholdConfig = {
  order: number;
  operatorType: ThresholdOperator;
  value: number;
  colorHex: string;
}

type ThresholdOutput = ThresholdConfig & {
  label: string;
}

type ThresholdTranslation = {
  label: string;
}

type VisualizationConfigTranslation = {
  label: string;
  description: string;
  thresholds: Record<string, ThresholdTranslation>; // keyed by threshold order
  seo: {
    keywords: string[];
  };
}

type SVC = {
  key: string;
  type: "visualizationConfig";
  unit?: string;
  thresholds: ThresholdOutput[];
  thresholdAxisLabelDisplayMode: ThresholdAxisLabelDisplayMode;
  showAverage: boolean;
  showMedian: boolean;
  showSum: boolean;
  showCount: boolean;
  showMax: boolean;
  showMin: boolean;
  showAverageOnChart: false;
  showMedianOnChart: false;
  showMaxOnChart: false;
  showMinOnChart: false;
  autoScaleYAxis: boolean;
}

```

Threshold labels are localized. Keep numeric threshold data in `model.json`, and define translated labels in each language file:

```json
{
  "label": "Sleep Hours",
  "description": "Monitor sleep duration for better rest quality and health",
  "thresholds": {
    "1": { "label": "Too short" },
    "2": { "label": "Short" }
  },
  "seo": {
    "keywords": ["sleep", "rest"]
  }
}
```

The build script merges each translation into the corresponding threshold, so generated bundles expose `thresholds` as an array where every threshold includes its localized `label`.
